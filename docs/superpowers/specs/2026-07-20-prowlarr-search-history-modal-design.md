# Prowlarr 搜索历史弹窗设计

## 目标

将 Prowlarr 搜索页内联展示的搜索历史改为左上角的“搜索历史”按钮。页面进入时不再请求历史记录或自动恢复最近一次搜索；用户点击按钮后才获取并在弹窗中展示历史。

## 交互与布局

- 在 Prowlarr 搜索页标题区域的左上角放置“搜索历史”按钮。
- 按钮始终可点击。没有历史记录时，弹窗显示明确的空状态。
- 每次点击按钮时，请求 `GET /api/prowlarr/search-history`，请求成功后打开弹窗并展示最新列表。
- 弹窗内的每条历史记录显示关键词、媒体类型与结果数量，并提供：
  - 点击记录：获取该记录缓存的结果，恢复关键词、媒体类型、排序和索引器选择；不重新向 Prowlarr 发起搜索；恢复成功后关闭弹窗。
  - 删除记录：删除单条记录并从弹窗列表移除；如果该记录正被展示，清空当前关键词与结果。
  - 清空记录：清空全部历史、清空当前关键词与结果，并保持弹窗打开以展示空状态。
- 关闭弹窗不改变当前搜索表单或结果。

## 数据流与错误处理

1. 初始化仅请求 Prowlarr 配置与索引器；不请求搜索历史，也不自动恢复结果。
2. 点击“搜索历史”按钮后调用现有列表接口；失败时显示现有错误提示且不打开弹窗。
3. 恢复、删除和清空继续复用现有详情、单条删除与清空接口；失败时保留当前弹窗和数据，显示现有错误提示。
4. 不新增后端接口、数据表或历史记录格式。

## 可访问性

- 使用项目现有动画弹窗组件和焦点管理约定。
- “搜索历史”按钮、关闭按钮、删除按钮与清空按钮均有清晰名称。
- 弹窗关闭时焦点回到触发“搜索历史”按钮。

## 测试

- 初次渲染不请求搜索历史，且不恢复最近一次搜索结果。
- 点击“搜索历史”后才请求列表并展示弹窗。
- 从弹窗恢复记录时仅请求缓存详情，不重新搜索，并关闭弹窗。
- 弹窗中的删除与清空保持现有同步清理行为，清空后展示空状态。

## 非目标

- 不改变搜索历史的持久化策略、最大保留数量或后端接口。
- 不增加历史分页、筛选或排序。
