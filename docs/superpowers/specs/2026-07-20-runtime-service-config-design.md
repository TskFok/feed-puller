# 运行时服务配置设计

## 目标

在设置页配置并持久化以下运行时服务参数，使保存后的新值立即用于后续请求：

- `ARIA2_RPC_URL`
- `ARIA2_RPC_SECRET`
- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `ARIA2_HOOK_SECRET`

`SESSION_SECRET` 不在本次范围内。

## 数据与接口

新增受现有登录态保护的 `GET` 与 `PUT /api/settings/runtime-config`。

响应与请求使用五个同名的 snake_case 字段。接口按需求返回完整明文，供设置页回显与编辑。

配置存入既有 `settings` 表，并为每个字段使用独立的、固定的设置键。启动时先读取环境变量；若数据库中已保存对应键，则以数据库值覆盖环境变量。这样已有部署无需迁移，且保存的空字符串可显式清空可选配置。

## 校验与错误处理

保存请求会去除字段首尾空白。非空 `aria2_rpc_url` 必须是绝对 HTTP 或 HTTPS URL；校验失败返回 400，且不写入数据库、不改变运行中的配置。其他四项允许为空，以支持关闭飞书能力或清除密钥。

数据库写入失败返回 500，运行时配置保持原值。只有全部配置成功写入后，才替换内存中的运行时依赖。

## 立即生效

服务维护可并发安全读取的运行时配置快照。

- 保存 Aria2 地址或密钥后，应用服务原子替换 Aria2 客户端；之后提交下载、查询状态和处理钩子关联任务均使用新客户端。
- 保存飞书 App ID 或 App Secret 后，HTTP API 的登录选项、OAuth 跳转和授权回调立刻读取新配置；下载通知发送器也会换成以新凭据构造的实例。
- 保存 Aria2 Hook 密钥后，下一个 `/api/downloads/aria2-hook` 请求立即按新密钥校验。

既有正在执行的请求继续使用它们开始执行时获取的依赖；本次保存不回滚或取消既有下载。

## 前端

设置页新增“运行时服务配置”面板，包含五个明文输入框及单个保存按钮。组件加载时读取接口，保存成功后以服务端返回值回填，并显示“运行时服务配置已保存并立即生效”；失败时显示接口错误。

## 测试

- 存储层：读取缺省值、保存与读取五项配置。
- HTTP API：未登录拒绝、读取、URL 校验失败、保存后回显，以及 Hook/飞书配置的热更新。
- 应用服务：Aria2 客户端替换后后续调用使用新地址或密钥。
- 前端：设置页加载五项值，提交时发出正确请求并显示成功反馈。
